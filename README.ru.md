# Personal Agent for BB — личный ИИ-помощник в Telegram

[English](README.md) · Русский

Попроси помощника в Telegram собрать исследование в PDF. Он передаст работу агенту в нужном проекте BB и пришлёт готовый файл в тот же чат. Позже можно открыть этот разговор в BB и продолжить с того места, где остановился. Для работы нужен собственный BB с подключённым Claude Code или Codex.

Это ранний выпуск для владельцев собственного экземпляра BB. Начни с личного чата и учебного проекта.

## Установка на машине BB

Эти шаги относятся к версии 0.2. Для старого ZIP сохранена [инструкция v0.1.9](https://github.com/ainurminibaev/bb-personal-assistant/blob/v0.1.9/README.md).

1. Подготовь BB 0.49 или новее, Git, Python 3 и провайдера Claude Code или Codex. Скачай установщик со [страницы релизов](https://github.com/ainurminibaev/bb-personal-assistant/releases) и открой распакованную папку на машине BB.
2. Выполни `bb machine list` и выбери ID этой машины. Для личных данных укажи отдельную рабочую папку. Установщик покажет источники обоих плагинов и попросит подтвердить установку.

   ```sh
   python3 setup.py --language ru --name "Личный помощник" --machine <ID-машины> --workspace ~/my-assistant
   ```

   Параметр языка задаёт язык меню Telegram при первой установке. При повторном запуске сохраняется язык, выбранный в BB.

3. Открой зарегистрированный проект в BB, создай тред «Личный помощник» и выбери модель. Создай своего бота через BotFather. В BB открой **Telegram → Подключение**, сохрани токен, включи синхронизацию и чат, затем открой ссылку привязки владельца.
4. В личном чате с ботом отправь `/project`, выбери проект, затем **Чаты → Личный помощник → Подключиться**. Повтори ту же команду установки. Она прочитает привязку и подключит инструкции к выбранному треду. Проверь результат командой `bb personal-assistant doctor`. Чтобы инструкции загрузились, возобнови этот же тред в свежей сессии провайдера.
5. Напиши боту и открой тот же разговор в BB. Из треда координатора команда `bb personal-assistant work` показывает его открытые рабочие треды.

Если в BB уже стоит исходный Telegram Projects, у него и у этого моста один идентификатор. Установщик остановится до любых изменений. Для отдельной пробы можно использовать другой экземпляр BB и нового бота. Действующие чаты продолжат работать в прежнем BB.

## Установка цифрового сотрудника

Цифровой сотрудник — та же платформа с настройкой `employee`: свой пользователь на сервере, свой бот, свои учётные записи и правила команды. Он отвечает всем участникам групп, куда его добавили, и после вашего одобрения — людям в личке.

1. На чистом сервере Ubuntu под root: `deploy/server-setup.sh <пользователь> <порт>`. Пока не проверен на чистой машине и в выпуск не входит. Скрипт создаёт системного пользователя с закрытыми папками, ставит Node, BB и агента в его каталог и запускает BB на localhost службой systemd.
2. Под этим пользователем войти в агента (Codex или Claude Code).
3. Запустить установщик с настройками сотрудника. Рабочая папка становится git-копией репозитория сотрудника (роль, правила команды, подключения), поэтому правки, которые он делает себе сам, — это коммиты:

   ```sh
   python3 setup.py --kind employee --machine <host-id> --workspace ~/workspace/<имя> \
     --workspace-repo <git-url> --provider codex --model <model-id> --inbox ~/telegram-inbox --allow-guest-guard
   ```

   `--provider` и `--model` запускают в проекте одну короткую проверку, BB запоминает их для новых разговоров. `--allow-guest-guard` одобряет хук гостевых тредов в Codex без интерфейса BB.
4. Создать бота, привязать его и свою личку, как в шагах выше. Коммиты и PR под именем сотрудника — [GitHub App](deploy/github-app.md).
5. Добавить бота в группу и сделать администратором: иначе Telegram показывает ему только ответы и команды, без отметок. Вам придёт короткое сообщение — что будет, если ничего не менять, и настройка в три шага.

| Настройка | Варианты | Когда что |
|---|---|---|
| Кто обращается в группе | все участники / только вы и люди с доступом | все — рабочая группа команды; только вы — если в группе посторонние |
| Когда отвечать | на отметку или ответ / на всё, что к нему по делу | отметка по умолчанию; второе — маленькая группа, где он ведёт процесс |
| Память группы | общая / только этой группы | общая — если в группе только вы; только этой — если есть другие люди |
| Личка людей | выключена / по вашему одобрению | включать, когда людям нужно работать с ним один на один |

## Обновление

Для смены провайдера нужны Personal Agent 0.2.3 и Telegram Bridge 0.9.21 или новее. Обнови оба компонента в одном окне обслуживания.

Установщик также ставит плагин **Knowledge Base** из папки `plugins/knowledge-base` того же выпуска. Его настройка `root` — папка базы на сервере BB, по умолчанию `~/knowledge-base`; при первом обращении там создаётся пустая база в git. Агенты любого проекта ищут, читают и добавляют материалы инструментами `kb_search`, `kb_read`, `kb_topics`, `kb_add`, есть и команда `bb kb`.

Все плагины получают совместимые релизы через **Настройки → Обновления** в BB. Команда `bb plugin outdated` проверяет наличие новых версий. Личный реестр, память, материалы и свои инструкции храни в рабочей папке, указанной в `--workspace`.

Установщик создаёт в рабочей папке пустой local/agents-custom.md при первом запуске. Добавляйте туда инструкции, которые должны пережить обновление и откат. Перед миграцией старой установки сверьте локальные изменения с её прежней версией. Для разделения прав на Linux используйте управляемую установку роли отдельным администратором.

Для перехода с v0.1.9 сначала выполни [однократный перенос источника моста](BRIDGE-MIGRATION.md). Затем передай новому установщику прежнюю рабочую папку. Существующий чат и тред остаются привязанными. Проверь свои локальные дополнения к старым инструкциям.

## Если бот молчит

1. Открой тред координатора в BB. Проверь, занят ли он поручением, ждёт ли ответа или сообщил о лимите провайдера.
2. В настройках Telegram сверь имя бота, привязанного владельца и оба переключателя приёма сообщений. Для лички достаточно привязки чата.
3. Выполни `bb personal-assistant doctor` на машине BB. Сверь выбранный в Telegram тред с координатором, особенно после смены провайдера.
4. Команда `bb telegram-projects chat-status --json` показывает очередь и ошибки доставки. В выводе есть идентификаторы привязок, поэтому его хранят у себя.
5. Проверь вход и лимит провайдера на машине исполнителя. Если поручение меняет данные, перед повтором сверь историю BB и сообщения в исходном Telegram-чате.

## Доступ в группах

Тема группы получает отдельный BB-тред. Это разделяет историю разговоров. Код, запущенный с правами того же системного пользователя, может иметь доступ к его файлам и инструментам. Для участников выдели отдельный BB и повторно привяжи тему к его треду. Начиная с версии моста personal.28 это требуется как для списка разрешённых участников, так и для режима «отвечать всем». Токен бота хранится у личного моста. Он отправляет результат ответом на исходное сообщение в группе. Владелец может пользоваться локальной темой один. [Настройка группового исполнителя](https://github.com/ainurminibaev/bb-plugin-telegram-projects/blob/v0.9.1/docs/isolated-groups.md).

Для исполнителя выполни отдельный вход в аккаунт провайдера. Сама по себе отдельная папка проекта не защищает ключ входа от процессов того же системного пользователя. До подключения участников отправь в нужную тему тестовый файл. Когда бот пришлёт PDF, ответь на него с правкой и проверь, что исправленный файл пришёл в ту же тему.

## История каналов личного аккаунта

На общем Linux-сервере с личным координатором и групповыми агентами настрой [службу приватной истории](telegram-account/PRIVATE-HISTORY.md). Её системный пользователь хранит ключ Telegram. Личный координатор получает только результаты запросов к выбранным каналам через локальный сокет. Для групповых тредов и их дочерних процессов нужны отдельные непривилегированные учётные записи. Запуск группового агента от root разрушает эту границу.

Следующие шаги для прямого запуска мастера относятся к выделенной доверенной машине одного владельца.

Необязательное подключение для Linux и macOS. Администратор каждой установки регистрирует собственное приложение в разделе API development tools на https://my.telegram.org. Каждый владелец подтверждает вход своим Telegram. Параметры приложения и ключ сессии хранятся в приватном каталоге машины за пределами проекта. Используйте доверенную машину и отдельного системного пользователя для личного помощника: произвольный код с правами того же пользователя может прочитать файлы его сессии. Запускайте чужие проекты и групповых агентов под отдельными системными пользователями, если нужна изоляция.

Сначала привяжите личного бота. На машине с BB установите утилиту qrencode (на Ubuntu пакет qrencode, на macOS формула Homebrew qrencode). В корне распакованного помощника:

    python3 -m venv ~/.local/share/pa-telegram-venv
    ~/.local/share/pa-telegram-venv/bin/pip install --require-hashes -r telegram-account/requirements.txt
    ~/.local/share/pa-telegram-venv/bin/python telegram-account/account.py configure
    ~/.local/share/pa-telegram-venv/bin/python telegram-account/account.py connect

Введите api_id и api_hash в терминале владельца. Откройте временную ссылку, напечатанную последней командой. На удалённой машине перед этим пробросьте порт с компьютера владельца командой ssh -L 18341:127.0.0.1:18341 <сервер>. Страница работает на 127.0.0.1, срок ссылки десять минут. QR сканируется авторизованным Telegram на втором устройстве. При включённой двухэтапной защите пароль вводится в этой странице. Мастер сверяет ваш ID с привязкой владельца в BB. Выберите разрешённые каналы. Повторный connect позволяет изменить выбор без нового входа; disconnect отзывает созданную мастером сессию. Существующая сессия tgparser управляется отдельно.

Из личного треда `search <числовой ID канала> <слова>` возвращает до десяти совпадений. Например:

    ~/.local/share/pa-telegram-venv/bin/python telegram-account/account.py search -1001234567890 Java

Каталог состояния по умолчанию ~/.local/state/personal-assistant/telegram. До завершения QR-входа и выбора каналов поиск недоступен.

Команда `channels` в том же личном треде показывает названия и ID разрешённых каналов.

Чтобы владелец мог начать вход прямо из лички, администратор один раз настраивает выделенное HTTPS-имя на своём reverse proxy с пересылкой на 127.0.0.1:18341 и передаёт это имя в `configure --origin https://<имя-мастера>`. После этого команда `open` из привязанного личного треда запускает мастер на десять минут и возвращает одноразовую ссылку для владельца. После сохранения выбора мастер завершается. При использовании локальной установки или SSH отдельный домен не требуется.

## Как устроено

Платформа одна, установки тонкие. Личный помощник и цифровой сотрудник — одна и та же платформа с разными настройками. В установке лежат только роль, правила команды, подключения и настройки; своего кода у неё нет.

Требование, которое пришло от одной установки, выполняется в платформе: общим изменением для всех либо описанным вариантом настройки. В установке остаётся только то, что относится к одному владельцу или одной команде. Правка, сделанная руками на одном сервере, не считается законченной, пока не попала в установщик или в документ запуска. Изменение платформы приходит во все установки одним выпуском.
