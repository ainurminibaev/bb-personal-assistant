# База знаний

База — git-репозиторий на сервере BB (путь задаёт настройка плагина
`Knowledge Base → root`, по умолчанию `~/knowledge-base` пользователя, под
которым работает BB; при первом обращении там создаётся пустая база).
Айтемы: `topics/<topic>/items/NNN-slug.md` с YAML frontmatter. Индексы
(`INDEX.md` и другие) генерирует `scripts/kb-rebuild.py` базы, а если его нет —
сам плагин. Руками не правь.
Собственные правила базы (темы, шаблон, инструменты разбора медиа) лежат в
её `AGENTS.md`/`CLAUDE.md`; `kb_topics` возвращает их в поле `rules`.

## Как обращаться

1. Инструменты агента (Claude Code и Codex, любая машина; выполняются на сервере BB):
   - `kb_search {query?, topic?, tag?, limit?}` — поиск; пустой запрос = новые айтемы.
   - `kb_read {ref}` — полный текст; ref = путь, slug, `NNN-slug` или `topic/NNN`.
   - `kb_topics {}` — темы, количество айтемов и правила базы.
   - `kb_add {...}` — новый айтем (см. ниже).
2. Если инструментов в сессии нет — тот же функционал через CLI на любой машине:
   `bb kb search [--topic T] [--tag X] слова`, `bb kb read <ref>`, `bb kb topics`,
   `bb kb add --topic … --title … --slug … --source … --type … --tags a,b --body-text '…'`.
3. На машине сервера можно читать файлы базы и `grep -r` по `topics/`.
   Не копируй базу на другие машины.

## Когда обращаться

- Вопросы о ранее сохранённых материалах: «у нас было…», «в базе есть…»,
  «что сохраняли про…», «тот рилс/гайд/репо про …».
- «Запиши / сохрани / добавь в базу», разбор рилса, ссылки, репо, PDF для базы.
- Перед исследованием темы полезно проверить, нет ли уже материала.

## Добавление (kb_add)

1. `kb_search` по источнику и ключевым словам. Если айтем уже есть — дополни
   существующий файл на сервере и пересобери индексы (`scripts/kb-rebuild.py`,
   если он есть в базе), а не создавай дубль.
2. `kb_topics` — выбрать существующую тему и прочитать правила базы.
3. `kb_add`: `topic`, `title`, `slug` (kebab-case латиницей, уникальный),
   `source` (URL), `type` (github-repo | article | ig-reel | person | product |
   how-to-guide | guide-pdf), `tags` (kebab-case), `status` (pointer |
   researched | in-progress), `body` — markdown без frontmatter и заголовка:

```
## Что внутри / Что делает
## Зачем нам
## Связанные айтемы
- [[other-slug]]
## Источник в чате
<откуда пришло: чат, сообщение, дата>
```

`kb_add` сам: отклоняет дубль по источнику (Instagram reel id, YouTube id,
GitHub owner/repo, URL) или slug (`status: duplicate`), ставит следующий id в
теме, пишет файл, пересобирает индексы и делает локальный коммит только своих
файлов (без push). Индексы попадают в коммит, только если до этого в них не
было чужих незакоммиченных правок. Новую тему (`createTopic`) — только если ни
одна не подходит. `dryRun: true` показывает итоговый файл без записи.

## Разбор рилса / видео / ссылки

Скачивание медиа, распознавание речи и загрузку страниц делай штатными
инструментами, перечисленными в правилах базы (`kb_topics` → `rules`); свои
загрузчики, модели и пакеты не ставь. С другой машины запускай их на сервере:
`bb terminal run --machine <сервер> …`. Временные файлы — в
`$BB_THREAD_STORAGE` или `/tmp`; в базу — только то, что нужно сохранить.
Вложения (картинки, PDF, raw-пакеты) кладутся рядом с айтемом или в `raw/`
на сервере и коммитятся отдельно, по именам файлов.
